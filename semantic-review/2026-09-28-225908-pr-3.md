# Deterministic compiler, semantic planner, CLI, and MCP service

Task #3 adds one shared compiler that turns strict JSON/YAML semantic specifications into deterministic, validated draw.io output, then exposes it through Typer and six FastMCP tools. It also adds an OpenAI-compatible planner limited to producing `DiagramSpec`, with local icon metadata supplying the allowed vocabulary. The reported deterministic render, registry, CLI, planner-transport, and MCP checks pass, but three boundary behaviors remain blocking. **Watch for:** **confirmed** incomplete diagnostics on semantic/geometry failures, **confirmed** raw invalid planner content replayed during repair, and **confirmed** bearer credentials allowed over plaintext HTTP.

**Verdict**: NEEDS_CHANGES

## High-level view

CLI and MCP entry points consistently hand semantic specs to `CloudDiagramCompiler`; geometry, rendering, and output verification remain compiler-owned. The **confirmed** gap is that semantic and geometry validators raise before the canonical report is constructed, so these failures lose stage summaries, merged gate counts, decisions, and structured findings.

The planner separates the untrusted request from its system policy, uses a closed schema and bounded local icon context, and allows only one repair. The **confirmed** repair history nevertheless includes the complete invalid first response rather than only sanitized validation errors.

Planner secrets are `SecretStr`, excluded from settings serialization and repr, and absent from the exercised errors and diagnostics. The **confirmed** transport gap is that `http://` endpoints remain valid while the adapter attaches a bearer credential whenever configured.

## Semantic and geometry failures bypass the canonical compiler report

`CloudDiagramCompiler._run` calls `semantic.raise_for_errors()` and `geometry.raise_for_errors()` before creating `ReportBuilder` (`src/cloud_diagram/compiler.py:302,312`). Either failure therefore escapes as `SemanticValidationError` or `GeometryValidationError`, not `CompilationError` carrying a `DiagnosticReport`. This is **confirmed** by compiling a schema-valid spec with an unavailable canonical icon: it raises `SemanticValidationError`, has no `report`, and produces no stage summaries.

Output failures do take the canonical report path, making failure behavior stage-dependent. CLI semantic/geometry failures collapse to prose, while MCP callers cannot consume the structured failure payload available for output errors. Build the report before terminating, preserve findings and available hard counts, mark unrun stages skipped, and raise one `CompilationError(report)` for every compiler-owned validation failure.

## Schema repair replays arbitrary model output

After first-response validation fails, `OpenAICompatiblePlanner.plan` creates a sanitized repair instruction but also appends `{"role": "assistant", "content": first_content}` to the retry (`src/cloud_diagram/planner/openai.py:65-70`). This is **confirmed** with a mock transport: a unique marker from the invalid response appears verbatim in the second payload.

The retry is required to use only sanitized validation errors. Replaying `first_content` can duplicate echoed user/project text and preserve forbidden coordinates, XML, paths, or other arbitrary output that sanitization excludes. Construct the retry from the original system/user messages plus the sanitized repair instruction, without the raw assistant response.

## Bearer credentials can cross an unencrypted planner connection

`Settings.llm_endpoint` uses `AnyHttpUrl`, which accepts plaintext HTTP (`src/cloud_diagram/settings.py:36`), while `_completion` attaches the API key as `Authorization: Bearer` without checking the scheme (`src/cloud_diagram/planner/openai.py:120-124`). This is a **confirmed** credential-exposure path for a non-TLS endpoint even though the secret remains redacted in process output.

Reject keyed planner configurations unless the endpoint is HTTPS. If local OpenAI-compatible servers need loopback HTTP, permit that only without a key or behind an explicit, narrowly scoped opt-in.
